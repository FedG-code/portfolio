# JS Reference Map

Overview: no build step, no modules, all IIFEs. Three.js r128 comes from cdnjs (async, in the `<head>` of `index.html` and of each project page).

| File | Loaded by | Purpose |
|------|-----------|---------|
| `greybox.js` (~305 lines) | `index.html`, project pages | Shared 3D stage (`window.Greybox`): `renderer()`, `Stage`, `capsule`, `stand`, `Clock`, `phURL`, `dragX`, easing helpers |
| `gallery.js` (~715 lines) | `index.html` | The Dolly Gallery homepage |
| `case.js` (~490 lines) | `index.html` | A case in the scene (`window.CaseMode`): parses the project file, bubble, case bar, trailer, University frames, URL |
| `shared.js` (~63 lines) | project files (plain pages) | Scroll reveal, lazy mp4 loops, title focus |
| `analytics.js` (~57 lines) | all pages | GA4 events: case_open, email_click, social_click, scroll_depth |

Retired code (card hand, page transitions, title flight, theme toolbar, paper plane, text destruction) is in `archive/` (see archive/README.md); none of it is loaded.

## gallery.js

Ported from `design/blockout/dolly-r4.html` (round 4 prototype). Grep for the names below; line numbers drift.

### Data
- `H`: city, About lead line and body.
- `P`: the five project sections in track order (About is section 0 and is not in `P`). Fields: `id` (also the URL hash), `t`, `sub`/`subM` (desktop/phone sub line on the section's 3D sign), `img` (still texture), `clip` (mp4 for the motion overlay), `px` (pixel art: nearest filtering), `ar`, `alt`, `marks` (gizmo chips/boxes in the plain list preview), `href` (project page, or `null` = no Open yet), `blurb` (the gallery bubble's summary: Over the Hill / Eve / Casino = their page's `.project-hero-desc` verbatim, checked by gallery-test), `cap` (the plain list's preview caption), `spec`, `logs` (the wall monitor's gallery facts; `spec[2]` = its Stack line), `head` (two headline figures for the monitor's case sheet; no bet figures), `sheet` (which `spec` rows the case sheet shows; University: Stack only), `items` (University Projects and Other Games: three entries, each `t`, `href` (page + anchor), `img` poster + `clip` loop + `ar`; item 0 is the main, big frame; `phURL()` stands in for a missing `img`). An items bay's overlay plays the clip of the item that is big (`secs[s].order`). Each frame entry in `secs[s].scr` carries its name label (`lab`).
- Section index (`G.sel`, key `data-i`) = About 0, then `P[i]` is section `i + 1`.

### Flow
1. `boot()`: tries `upgrade()`; if Three.js isn't there yet (or no WebGL / `?flat`) it renders `flatList()`.
2. `three-ready` event (dispatched by the `<script onload>` in `<head>`) -> `upgrade()` keeps the selected section and focus.
3. `buildDolly(start)`: builds stage + shot list (`.keys`) + live region; `start = {sel, focus, pull}`.
4. Window width change -> rebuild (same renderer) keeping `G.sel`. Height changes are ignored (phone URL bars).

| `GB.quad(el, q)` (greybox.js) | Warps a `.pin` element onto four projected corners `[tl, tr, br, bl]` with a `matrix3d` homography (laid out at their bounding box), returns the box. | `divider(x)` (gallery.js) | A bay divider = a visible box that only receives shadows + an invisible caster (`SHM`: no colour, no depth, `shadowSide = FrontSide`) inset .1 on the lit sides (the sun is at -x, +y, +z) and running .3 into the wall and floor. r128 draws back faces into the shadow map, so the visible box's own shadow-side face sat within a texel of the wall and floor and a lit band leaked along every join; overlap and bias didn't fix it. The caster isn't in `hits`, so `st.pick` never sees it. |
| `GB.clip(src, poster, rm)` / `clipPut(o, v)` / `clipGate(o, v)` (greybox.js) | The clip cache, shared by the gallery overlay and the case's overlays: `<video>`s kept by src (up to 5; least recently used, never one showing, is evicted with `removeAttribute('src'); load()`), moved between overlays instead of rebuilt; spare ones wait paused in a 1px `.vhold` holder. `clipGate` adds `.wait` (opacity 0) until the video has a frame (readyState >= 2, not seeking; checked on `loadeddata` / `seeked` / `playing` / `timeupdate` and `requestVideoFrameCallback`, whichever comes first), and only if it is still that overlay's video; a video that already has a frame shows at once; with a `GB.START[src]` it also waits for that time on the first play. ### Accessibility
- The shot list is the keyboard route: roving tabindex, arrows/Home/End select, Enter on the selected section opens.
- `.live` (`aria-live=polite`, visually hidden) gets only the section name, and only on user-driven moves.
- The bubble (`#guide-bubble`) is the `aria-describedby` of the active key. The section titles and the About card are 3D signs (meshes: nothing to hide); a section's name is in the bar and the live region, the About text in a visually hidden `.sr` section.
- Return focus: the section's key. Opening a case moves focus to its current part on the case bar; closing returns it to the section's key.
- `prefers-reduced-motion`: `Clock.add` completes tweens instantly, no walk, no bubble pop, no motion overlay, no push/pull.

### Gotchas
- **No flash of the plain list**: an inline `<head>` script adds `html.g3d-wait` (unless `?flat` or no WebGL support), and gallery.css hides `#gallery`'s children behind a stage-shaped placeholder. It's removed when the gallery is built (before anything takes focus: hidden elements can't hold focus), on the `three-failed` event (script `onerror`), or after 4s, when the plain list shows. A `#section` return focus that couldn't land on the hidden list is carried by `G.wantFocus`.
- `[hidden]{display:none !important}` in gallery.css is required: `.bub{display:grid}` would otherwise beat the UA `[hidden]` rule and the bubble would never hide.
- If Three.js arrives after the plain list was shown, a pending pull-back (`G.pull`) is applied on upgrade unless the visitor already moved (`G.moved`).
- Don't give page elements ids equal to section ids (`over-the-hill`, ...): the back link's hash would scroll to them.

## case.js (a case in the scene)
"On Set" (direction C) in the gallery's own scene. `gallery.js` hands it the scene as `X` (`G.cs = CaseMode({...})`: stage, clock, guide, `secs`, `sx`, bars, `pushTarget`, `standToSpot`, `galleryShot`, `atGallery`, `setBusy`). Grep for the names below.

| Name | Notes |
|------|-------|
| `load(p)` / `parse(doc, p)` | Fetches the project file (cached; scripts don't run) and reads it: no Overview part (2026-11-23: the hero is the gallery summary); one part per `<p>` in `.project-content div.project-text`; a `<ul>` joins the `<p>` before it (lead line + bullets) or, straight after an `h4`, is a part of its own (`b.html` holds the wrapped elements; `fill()` sets it as is). A `div.part` is one part with all its paragraphs (Fishing). The first part with no capture of its own falls back to the gallery capture; a text-less section's trailer (Eve) goes to the part before it, or the first part. Bar groups = `h2` sections when there are 2+, else the `h4`s (Over the Hill). Captures = the block's `video[data-src]` / `img.work-image` (max 2, carried forward). `.work-stats` -> stat chips (desktop: the Now row of `caseHTML(i)` on the wall monitor via `X.wl`; phone: `.cstats` at the end of the bubble); `.project-link` -> tags; `.video-embed iframe` -> trailer; a `video[data-sound]` capture (Rally) -> "Play with sound" (`snd(b)`). Sections of an items bay map to `items` by id (`item`); `own` marks a part whose capture comes from its own section (not carried over). |
| `enter(s, k, o)` | `o.inside`: start inside the screen; `o.push`: push in first (Forward); `o.cut`: no motion (reduced motion, rebuild); `o.user`: pushes `#<id>/case` to history; `o.part`: start part. Hides the section bar, builds the case bar, low shot (`lowShot()`: desktop from 3.0 left of the stand to the bay's right end, taking in the monitor's right edge + .3, and on the smallest stages widened left so a 220 px bubble fits left of the screen; phone adds the guide's depth), wall monitor: flies to the case side with `caseHTML()` (sheet + Now row; `o.direct` / `o.cut` / RM place it at once), never blank in a case, `walkIn()` onto the stand, then `talk()`. If the file fails to load: the plain page (`?flat`). |
| `show(i, talk)` / `go(i, user)` | Part i: an items bay rotates its game big (`rotateTo`) and the big frame shows the part's own capture (`partCap(b)`: Stealth Game's three parts each have a clip), else its game's; the small frames and leaving restore each frame's own still; otherwise `setImg` on the main screen; two captures split it (`setSplit`: the still is hidden, the two overlays fill the screen's halves, `.vov.half` = contain; the bubble and tags measure the full screen then), clip overlays (`clips(b)`: videos from `GB.clip`, gated with `clipGate` when new; reduced motion: paused with controls, no gate), tags (items bay: beside the big frame's name label, or a row under it when they don't fit), Play button. Live region "Part i of N: heading" on user moves only. Between parts only the bubble's text cross-fades (`.t.anim`), the bubble doesn't re-enter. Desktop case bubble: right edge left of the screen and of the sign (`signRect`), top below the sign if the guide stands so close that they share columns; 220-500 px wide. |
| `leave()` / `exit(done)` | All projects: `history.back()` if we pushed the state (popstate closes), else replace the hash and close. Kills a walk-in still running (`inT`: browser Back during the walk-in used to leave the case bubble showing over the gallery). The wall monitor flies out, and drops back in on the left with the facts once the camera is at the gallery shot. Restore the screen's own capture, swap bars (scroll kept), pull straight back to the gallery shot (no push in), `standToSpot`. Phone `enter` shows the bubble with the case bar and keeps the scroll. |
| `trailer()` / `closeTrailer()` | Zoom into the frame (`inside()`; the monitor's HTML face hides until the zoom back out), YouTube embed (or, for a `data-sound` clip, a `<video controls>` played with sound from its `GB.START` time, like the loop; muted if the browser refuses) over the screen, Close button + Esc (focus stays on Close: the player frame would keep Esc). |
| `setupSlots()` / `rotateTo(k, dur)` / `rotateBay(s, k, dur)` | Frames (University, Other Games): `sec.order[k]` = slot of item k (slot 0 = big). Rotation tweens every frame to `sec.place(n, order[n], k)` (position + a uniform scale = slot width / its own width), updates `sec.scr[k].scx/sy/sw` (so `pushTarget` follows) and the selection outline's margin. `rotateBay` is the gallery's rotate-first before the push. |
| popstate | `#<id>/case`: open (or switch from another case); anything else: close. |

Gotchas: `st.pick` (greybox.js) only counts visible meshes: r128 raycasts hidden objects too, and line outlines are hit up to a unit away, so a hidden selection outline used to steal clicks meant for the next frame. While a case is open the stage doesn't scrub but clicks still reach `tap()` (gallery's drag `start` checks `inCase()`); the case bubble is `#case-bubble` (`.bub.cbub`), the gallery's is `#guide-bubble`; phone puts the case bubble in `.cmb` under the stage.

## shared.js (plain project pages)
- Scroll reveal (`.reveal` -> `.visible`), `window.revealObserver`.
- If `sessionStorage['dolly-return']` is set (the plain list's links set it): focus `.project-hero-title` (tabindex=-1), or, when the URL has `#item`, that section's `.section-heading`. Focus runs after `load` because the browser's own fragment focus step would undo it.
- `video[data-src]`: src set when within 200px of the viewport, play while visible, pause when not. Reduced motion: `controls`, no loop, `preload=none`, no autoplay.
